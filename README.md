# FlowTrack

FlowTrack — веб-приложение для личной продуктивности и совместной работы:
задачи, проекты, привычки, заметки, цели, фокус-сессии и отдельные Team
Workspace для семьи, команды или рабочих проектов.

Приложение работает на компьютере и телефоне. Каждый пользователь входит через
свой аккаунт ChatGPT и получает отдельный личный кабинет с изолированными
данными. Общие данные появляются только внутри Team Workspace, в которое
пользователь вступил или которое создал сам.

- **Последнее обновление документации:** 31 июля 2026 года
- **Язык интерфейса:** русский
- **Автоматические проверки:** 45/45
- **Рабочий сайт:** [flowtrack-personal.andrewkim2002.chatgpt.site](https://flowtrack-personal.andrewkim2002.chatgpt.site)

## Быстрый старт

1. Откройте [FlowTrack](https://flowtrack-personal.andrewkim2002.chatgpt.site).
2. Нажмите **«Войти или зарегистрироваться»**.
3. Авторизуйтесь через аккаунт ChatGPT.
4. При первом входе FlowTrack автоматически создаст отдельный личный кабинет.
5. Добавьте первую задачу, привычку или проект.
6. После накопления данных откройте **«Аналитику»**, чтобы сравнить план и
   фактический результат.
7. Для совместного проекта откройте **Team Workspace**, создайте пространство и
   пригласите участников по email их аккаунтов.

Подробные пользовательские сценарии описаны в
[мини-гайде](docs/USER_GUIDE.md).

## Навигация

На компьютере основные разделы находятся в боковой панели. Её можно оставить
развёрнутой, сделать компактной или переключить в автоматический режим.

На телефоне нижняя панель содержит пять читаемых пунктов:

1. **Сегодня**
2. **Привычки**
3. **План**
4. **Проекты**
5. **Ещё**

В **«Ещё»** находятся аналитика, печать, таймер, заметки, цели, Team Workspace,
быстрое добавление, настройки, данные и администрирование. Поиск и профиль
доступны в верхней панели. Мобильная компоновка учитывает безопасные зоны
устройства.

## Аналитика

Текущий модуль является интерактивным дашбордом. Он рассчитывает:

- выполнение плана;
- долю задач, завершённых в срок;
- завершённое фокус-время;
- регулярность привычек;
- число завершённых, незавершённых и перенесённых задач;
- распределение результатов по проектам;
- ежедневный ритм на графике и календаре активности.

Показатели сравниваются с предыдущим календарным периодом. Расчёты учитывают
местную дату и часовой пояс пользователя. Завершения задач, отметки привычек и
фокус-сессии восстановлены из существующих данных; точная история переносов и
повторных открытий начинает накапливаться с версии 20.

Дашборд автоматически пересчитывается после изменения исходных данных. Кнопка
**«Обновить данные»** позволяет немедленно запросить новый снимок вручную.
Удалённые задачи, привычки, проекты и записи фокуса не участвуют в живых
показателях; восстановление записи из корзины возвращает её вклад.

Сейчас модуль ещё не создаёт отдельный сохраняемый аналитический отчёт и не
экспортирует его в PDF или Excel. Подробные формулы, границы достоверности и
устройство событийной истории описаны в [спецификации аналитики](docs/analytics.md).

## Печать и шаблоны

Раздел **«Печать»** создаёт отдельные листы A4 для недели, месяца и дня. Нажмите
**«Печать / PDF»**, чтобы отправить выбранный лист в системный диалог печати или
сохранить его как PDF. В шаблон попадают названия привычек и пустые поля для
ручных отметок; его создание никогда не засчитывает выполнение автоматически.

После недельной распечатки откройте блок **«Внести отметки с бумаги»** и
перенесите только реальные выполнения. Эти отметки сохраняются как обычные
данные привычек и затем участвуют в аналитике.

## Team Workspace

Team Workspace — отдельный совместный контур FlowTrack. Он подходит для
семейных дел, учебной команды и рабочих проектов, не превращая личный кабинет в
общий.

Первый рабочий выпуск позволяет:

- создать несколько пространств и переключаться между ними;
- выбрать сценарий «Семья», «Команда» или «Работа»;
- создать общие проекты с канбан-доской;
- добавлять, редактировать, назначать и перетаскивать общие задачи;
- приглашать участника по email его аккаунта ChatGPT;
- принять или отклонить приглашение внутри FlowTrack;
- назначать роли владельца, администратора, участника и наблюдателя;
- просматривать журнал основных действий.

Владелец и администратор управляют приглашениями и проектами. Участник может
работать с задачами в доступных проектах, а наблюдатель имеет доступ только для
чтения. Все права повторно проверяются сервером.

Личные привычки, заметки, цели, таймеры, аналитика и резервные копии не входят
в Team Workspace и не открываются другим участникам. Приглашение действительно
14 дней и появляется после входа с тем email, на который оно создано.

## Работа с ChatGPT и JSON

FlowTrack поддерживает три вида выгрузки:

| Вид | Назначение | Поведение при импорте |
| --- | --- | --- |
| Контекст для ChatGPT | Передать активные проекты, задачи, привычки и цели для планирования | Не импортируется обратно как резервная копия |
| `flowtrack-backup` | Полная копия кабинета, включая историю времени и корзину | Полностью заменяет текущие данные после подтверждения |
| `flowtrack-plan` | План, созданный вручную или с помощью ChatGPT | Добавляет новые записи, пропускает совпадения и поддерживает отмену |

Перед любым импортом приложение автоматически скачивает текущую резервную
копию. Максимальный размер загружаемого JSON-файла — 15 МБ.

Готовый пример и рекомендуемый запрос для ChatGPT приведены в разделе
[«Планирование с ChatGPT»](docs/USER_GUIDE.md#15-планирование-с-chatgpt).

### Влияние восстановления на аналитику

После полного восстановления FlowTrack заново строит доступную базовую историю
аналитики по загруженным задачам, привычкам и фокус-сессиям. События переносов
или повторных открытий, которых нет в старой копии, восстановить задним числом
невозможно.

## Учётные записи и приватность

- Вход и выход выполняются через Sign in with ChatGPT.
- Email служит стабильным идентификатором пользователя.
- Имя профиля используется для отображения и персонального приветствия.
- Проекты, задачи, привычки, таймеры, заметки, цели, импорты и события
  аналитики привязаны к текущему пользователю.
- Общие проекты и задачи хранятся отдельно с `workspaceId`; доступ определяется
  активным членством и ролью, а не идентификатором из браузера.
- Приглашение можно принять только из аккаунта с совпадающим email.
- Все операции чтения и изменения проходят серверную проверку пользователя.
- Клиент не передаёт произвольный `userId` для доступа к данным или аналитике.
- Администратор видит аккаунты, даты активности и количество записей, но не
  тексты заметок, задач и целей.
- Роль владельца закрепляется за email из серверной переменной
  `FLOWTRACK_OWNER_EMAIL`.
- Параметры внешнего вида хранятся локально на устройстве и не передаются между
  компьютером и телефоном.

Если имя профиля недоступно, FlowTrack не выводит email в приветствии и
использует нейтральную формулировку.

### API

Основные изменения отправляются в `/api/data` как действия, например
`createTask`, `reorderKanbanCards`, `setHabitCompletion`, `startPomodoro`,
`importPlan` или `restoreBackup`. Сервер самостоятельно определяет текущего
пользователя.

Аналитика загружается через `GET /api/analytics`. Эндпоинт принимает период,
опорную дату, местную сегодняшнюю дату, смещение часового пояса и необязательный
фильтр проекта.

Team Workspace загружается через `GET /api/team`, а его изменения отправляются
как действия в `POST /api/team`. Сервер для каждого запроса заново определяет
пользователя, членство и роль.

### Модель канбана

Задача является единой сущностью для расписания и канбан-доски. Положение
хранится в `kanbanColumnId` и `kanbanOrder`, а перенос между колонками
синхронизирует статус `todo`, `doing` или `done`. Это предотвращает расхождение
между отдельной «задачей» и отдельной «карточкой».

### Событийная модель аналитики

Миграция `0004_nappy_songbird.sql` создаёт `analytics_events`,
`analytics_tracking`, необходимые индексы и 13 SQLite-триггеров. События
фиксируют создание, завершение, повторное открытие, перенос срока, удаление и
восстановление задач, отметки привычек и завершённые фокус-сессии.

## Локальная разработка

### Требования

- Node.js `>=22.13.0`;
- Linux или WSL2;
- `flock`, `curl` и GNU `timeout`;
- доступ к D1-привязке `DB` для сценариев, использующих базу данных.

### Установка и запуск

```bash
npm run install:ci
npm run dev
```

### Проверка

```bash
npm run lint
npm test
```

`npm test` сначала создаёт production-сборку, проверяет артефакт, а затем
запускает все тесты Node.

Для отдельной проверки готового артефакта:

```bash
npm run validate:artifact
```

### Изменение схемы БД

1. Обновите `db/schema.ts`.
2. Создайте миграцию:

   ```bash
   npm run db:generate
   ```

3. Проверьте SQL-файл и снимок схемы в `drizzle/`.
4. Разверните всю цепочку миграций на пустой тестовой базе.
5. Не выполняйте `CREATE`, `ALTER` или `PRAGMA table_info` внутри
   пользовательских запросов: миграции применяются при развёртывании.

## Ограничения версии 25

- Аналитика пока является дашбордом: нет сохранения и экспорта аналитических
  отчётов в PDF или Excel. Раздел «Печать» формирует рабочие листы, а не
  аналитический отчёт.
- Точная история переносов сроков и повторных открытий задач начинается только
  с версии 20.
- Привычки пока глобальны и не меняются при фильтрации аналитики по проекту.
- Нет офлайн-режима, PWA-установки, APK и push-уведомлений.
- Администратор пока не может блокировать или удалять пользователей.
- Резервные копии создаются вручную, автоматического расписания пока нет.
- Нет полного E2E-набора для drag-and-drop на компьютере и телефоне.
- Основной `flowtrack-app.tsx` остаётся крупным, хотя TipTap уже вынесен из
  стартового пакета.
- В Team Workspace пока нет комментариев, вложений, уведомлений, передачи
  владения и отдельного экспорта общего пространства.
- Перед массовым запуском нужны нагрузочные тесты, мониторинг, политика
  хранения данных, поддержка и отдельный инфраструктурный план.

## История проекта

FlowTrack собран на основе анализа двух прототипов:

1. исходного приложения `all-in-one-productivity-application`;
2. альтернативного проекта `glm 5.2`, использованного как референс удобства и
