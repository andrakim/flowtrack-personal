# FlowTrack Personal

FlowTrack — персональное веб-приложение для управления задачами, проектами,
привычками, заметками, целями и фокус-сессиями в одном пространстве.

Приложение рассчитано на использование с компьютера и телефона. Каждый
пользователь входит через свой аккаунт ChatGPT и получает отдельный личный
кабинет с изолированными данными.

- **Статус:** рабочая бета-версия
- **Текущая документированная версия:** 11
- **Язык интерфейса:** русский
- **Рабочий сайт:** [flowtrack-personal.andrewkim2002.chatgpt.site](https://flowtrack-personal.andrewkim2002.chatgpt.site)

| Привычки | Ежедневные, будничные и еженедельные привычки, отметки выполнения и серии |

| Проекты | Проекты с собственной канбан-доской, перетаскивание колонок и карточек, автоматическое изменение статуса задач |
| Таймер | Свободный учёт времени и отдельный режим Помодоро с фокусом, короткими и длинными перерывами |
| Заметки | Поиск, теги, закрепление, цвет и форматирование текста |
| Цели | Категории, дедлайны, числовой прогресс, единицы измерения и завершение |

## Быстрый старт для пользователя

1. Откройте [FlowTrack](https://flowtrack-personal.andrewkim2002.chatgpt.site).
2. Нажмите **«Войти или зарегистрироваться»**.
3. Авторизуйтесь через свой аккаунт ChatGPT.
4. При первом входе FlowTrack автоматически создаст отдельный личный кабинет.
5. Начните с быстрой задачи, привычки или первого проекта.

Подробная инструкция находится в
[пользовательском мини-гайде](docs/USER_GUIDE.md).

## Работа с ChatGPT и JSON

FlowTrack поддерживает три вида выгрузки:

| Вид | Назначение | Поведение при импорте |
| --- | --- | --- |
| Контекст для ChatGPT | Передать активные проекты, задачи, привычки и цели для планирования | Не импортируется обратно как резервная копия |
| `flowtrack-backup` | Полная копия кабинета, включая историю времени и корзину | Полностью заменяет текущие данные после подтверждения |
| `flowtrack-plan` | План, созданный вручную или с помощью ChatGPT | Добавляет новые записи, пропускает совпадения и поддерживает отмену |

Перед любым импортом приложение автоматически скачивает текущую резервную
копию. Максимальный размер загружаемого JSON-файла — 15 МБ.

Готовый пример и рекомендуемый запрос для ChatGPT приведены в разделе
[«Планирование с ChatGPT»](docs/USER_GUIDE.md#12-планирование-с-chatgpt).

## Учётные записи и приватность

- Вход и выход выполняются через Sign in with ChatGPT.
- Email служит стабильным идентификатором пользователя.
- Имя профиля используется для отображения и персонального приветствия.
- Проекты, задачи, привычки, таймеры, заметки, цели и импорты привязаны к
  текущему пользователю напрямую либо через родительскую запись.
- Все операции чтения и изменения проходят серверную проверку пользователя.
- Администратор видит аккаунты, даты активности и количество записей, но не
  тексты заметок, задач и целей.
- Роль владельца закрепляется за email из серверной переменной
  `FLOWTRACK_OWNER_EMAIL`.

Если имя профиля недоступно, FlowTrack не выводит email в приветствии и
использует нейтральную формулировку.

## Архитектура

| Путь | Ответственность |
| --- | --- |
| `app/page.tsx` | Публичная страница входа и подключение кабинета |
| `app/flowtrack-app.tsx` | Основной клиентский интерфейс и пользовательские сценарии |
| `app/admin/page.tsx` | Серверная панель владельца |
| `app/chatgpt-auth.ts` | Получение личности, безопасные адреса входа и выхода |
| `app/dashboard-greeting.ts` | Имя и приветствие с учётом местного времени |
| `app/api/data/route.ts` | Единый защищённый API чтения и изменения данных |
| `app/api/data/current-user.ts` | Создание пользователя, обновление активности и назначение роли |
| `app/api/data/backup.ts` | Проверка и восстановление полной резервной копии |
| `app/api/data/plan.ts` | Проверка, предварительный просмотр, импорт и отмена плана |
| `db/schema.ts` | Схема D1 и связи между сущностями |
| `drizzle/` | Версионируемые миграции базы данных |
| `tests/` | Проверки сборки, входа, ролей, импорта, БД и приветствия |

Основной API использует одну точку `/api/data`. Изменения отправляются как
действия, например `createTask`, `reorderKanbanCards`, `startPomodoro`,
`importPlan` или `restoreBackup`. Сервер определяет пользователя самостоятельно
и не принимает `userId` от клиента.

### Модель канбана

Задача является единой сущностью для расписания и канбан-доски. Положение
хранится в `kanbanColumnId` и `kanbanOrder`, а перенос между колонками
синхронизирует статус `todo`, `doing` или `done`. Это предотвращает расхождение
между отдельной «задачей» и отдельной «карточкой».

## Локальная разработка

### Требования

- Node.js `>=22.13.0`;
- Linux или WSL2;
- `flock`, `curl` и GNU `timeout`;
- доступ к D1-привязке `DB` для сценариев, использующих базу данных.

### Установка и запуск

```bash
npm run install:ci
npm run dev
```

Для обычной проверки:

```bash
npm run lint
npm test
```

`npm test` сначала создаёт production-сборку, проверяет артефакт и затем
запускает автоматические тесты.

### Изменение схемы БД

1. Обновите `db/schema.ts`.
2. Создайте миграцию:

   ```bash
   npm run db:generate
   ```

3. Проверьте новый SQL-файл в `drizzle/`.
4. Не выполняйте `CREATE`, `ALTER` или `PRAGMA table_info` внутри пользовательских
   запросов. Миграции применяются при развёртывании.

## Автоматические проверки

Текущий набор тестов проверяет:

- страницу входа для анонимного посетителя;
- кабинет для авторизованного пользователя;
- наличие корректной ссылки выхода и кнопки профиля;
- поддержку крупных числовых финансовых целей;
- назначение роли владельца только настроенному аккаунту;
- отсутствие миграций БД внутри пользовательского запроса;
- имя в приветствии;
- смену приветствия по местному времени;
- безопасный вариант без вывода email вместо имени.

## Ограничения текущей версии

- Нет отдельной регистрации по email и паролю: используется аккаунт ChatGPT.
- Нет офлайн-режима, PWA-установки, APK и push-уведомлений.
- Администратор пока не может блокировать или удалять пользователей.
- Резервные копии создаются вручную, автоматического расписания пока нет.
- Основной клиентский пакет крупный; перед массовым запуском потребуется
  разделение кода и дополнительное нагрузочное тестирование.
- Текущий хостинг подходит для личного и ограниченного семейного использования.
  Для массового продукта потребуется отдельно спроектировать инфраструктуру,
  мониторинг, лимиты, поддержку и юридические процессы.

## История проекта

FlowTrack собран на основе анализа двух прототипов:

1. исходного приложения `all-in-one-productivity-application`;
2. альтернативного проекта `glm 5.2`, использованного как референс удобства и
   визуального стиля.

Функциональная основа первого проекта была объединена с более лёгкой
интерфейсной подачей второго, после чего были добавлены собственные механики,
серверное хранение, личные кабинеты и защита данных. Полная хронология
зафиксирована в [отчёте о разработке](docs/DEVELOPMENT_REPORT.md).
